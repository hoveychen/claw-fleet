写给在用 dsh CLI 的人

钥匙是你自己的。
工作台给你配好。

DeepSeek Harness 是一个自带 key 的 harness：provider 由你配，能用到哪些模型取决于那些 key 打开了什么。Claw Fleet 是一个桌面应用，替它套上一个工作台——模型选择器里就是你的 provider 目录，花销读的是真正给你开账单的那一家，任务、决策与产出的收法和其他工具完全一样。

模型就是你 provider 的模型

dsh 会公布你的配置能触达的东西，所以选择器是按你的目录搭出来的，不是一份写死的清单。模型 id 带 provider 前缀，Fleet 按厂商分组，于是几十条的目录仍然是你能挑得动的。

推理档位在这里是按模型的，不是按工具的：每个模型带着它接受的那一套档位，菜单上还标出 dsh 自己的默认值，于是「我没选」这个状态会告诉你实际会发生什么，而不是让你猜。有些模型根本不暴露推理控制，那就没有档位可显示。

只有 dsh 真的装了，Fleet 才把它列出来。和另外两个 source 不同，这一个要通过一个它得先起来的服务才能拿到会话，所以没装 dsh 的机器上不会多出一个半死不活的菜单项。

花了多少钱，来自 provider 而不是我们

dsh 没有账号、配额或限流这一面——这不是漏了，而是由这个 harness 是什么决定的：配额属于你那把 key 背后的那家 provider。

所以 Fleet 去它真正存在的地方读：provider 自己的 API。对你配好的 key 来说，那意味着那家上报的余额与生成花销——那也是唯一和真实账单对得上的数字。没有套餐窗口可画，因为 dsh 没有套餐。

单会话的 token 记账是另一个问题，而这个 dsh 确实答得了——Fleet 读它公布的按会话 token 投影，所以你仍然能看到某个具体任务的 token 与费用估算。

所有会话背后是同一个本地服务

Fleet 通过一个本地 dsh 服务跟所有 dsh 会话说话，并且把它当成一个机器级的服务，而不是随某个窗口一起消亡的子进程。关掉应用再打开，它接管正在跑的那个服务，而不是再起第二个。

这本来是你得自己伺候的那一块，也是最容易悄悄出错的那一块：两个服务、两个端口、会话分在两边。租约连端口与启动令牌一起记下来、只有你读得到，所以后来一次健康检查失败可以重启同一个服务，而不是把它扔在那儿。

同一块板、同样的决策、同样的产出

工作台围着会话做的一切，在这儿一样管用。dsh 任务和其他任务同在一块板上，卡片标着 provider 与模型；跑着的时候能追加指令、能带着材料弹出决策卡、做完的文件落进项目的产出里。

图片双向都通：给简报附上参考图，它们以真实文件的形式送到会话手里。

dsh 会话里写下的计划，就是另一个工具接手的那一份；交接时可以指定用 Claude Code 或 Codex 的模型继续。自带 key 的 harness 的意义本来就是不必把自己绑死——把计划、知识库和成果放在 CLI 之外，才让这件事在实际使用中成立。

钥匙放在哪

provider 凭据留在你自己的 dsh 配置里。Fleet 能告诉你某个会话需要的凭据在不在，因为那正是 dsh 上报的东西——只是「在不在」，不是 key 本身，也不是挂在它上面的余额。

Fleet 跑在你自己的机器上、紧挨着 dsh，免费开源，协议 AGPL-3.0，不额外引入任何账号。那台机器要在线，它的任务才动得了；手机是连回它，而不是替代它。

大家先问的几个问题

我到底能用哪些模型？+

你配好的 provider 暴露出来的那些——dsh 公布那份目录，Fleet 按它搭选择器。常见情况是 dsh 声明的一堆 provider 里只有少数几个是活的，没激活的那些不会来挡你的路。

Fleet 需要我的 provider key 吗？+

不需要。它们留在你的 dsh 配置里。Fleet 只问 dsh「某个会话要的凭据设了没有」——那是在不在，不是 key；花销则用你已经授权的访问，从 provider 的 API 读。

为什么这里的档位菜单和 Claude Code 那边不一样？+

因为这里是按模型的。每个 dsh 模型带着它接受的那套推理档位与 dsh 自己的默认值，而不暴露推理控制的模型干脆不显示档位。

dsh 那个服务要我自己起吗？+

不用。Fleet 起一个本地服务，下次打开时再接管同一个，所以会话不会被分到两个服务上去。
