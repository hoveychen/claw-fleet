工具、模型，以及两者的区别

Fleet 能驱动什么，
又不能驱动什么。

两个问题常被混在一起：Fleet 能起哪个 agent 工具，以及那个工具能用到哪些模型。Fleet 驱动三个工具；而通过它们——尤其是通过一个自带 key 的 harness——你能触达相当多的模型。这一页把两者分开讲，让你一分钟内看得出自己那套装备合不合。

目前驱动的三个

Claude Code。Fleet 起你装好的 CLI、读它写下的会话文件，给出 Claude 自己的模型目录与那五级推理档位，并显示它上报的账号配额窗口。Claude Code 在 Fleet 里的样子。

Codex。形态相同，用 Codex 自己的目录和另一套档位刻度，记在你的 ChatGPT 套餐上。无人值守的运行也能弹出决策卡，还能借它自带的图像 skill 出图。Codex 在 Fleet 里的样子。

DeepSeek Harness（dsh CLI）。一个自带 key 的 harness：模型是你配好的 provider 暴露出来的那些，档位按模型走，花销读的是真正给你开账单的那一家。DeepSeek Harness 在 Fleet 里的样子。

一个工具要怎样才接得进来

这三个不是随手挑的——它们形态相同：都是跑在你自己机器上的命令行 agent，都把会话记成 Fleet 读得到的文件，都能用一条命令起来和恢复。正因为是这个形态，Fleet 才能跟上一个不是自己起的会话、在重启之后接着恢复、把一个决定挂回提问的那次运行、以及把一份计划从一个工具交到另一个手里。

反过来搭的工具——自己的云、自己的编辑器、会话在它自己的服务里——那是另一种接入，而不是清单上少写的一行。这也是为什么这份清单短，以及为什么每加一个都是真的工作量，不是加一条配置。

模型是另一个问题

工具决定活怎么跑，provider 决定活能用哪些模型。通过 dsh，第二份清单相当宽：你配上手里有 key 的 provider，Fleet 的目录就按它们暴露的东西搭出来——来自很多厂的模型，按厂商分组，各带自己接受的推理档位。

所以「我能不能用某个模型」和「我能不能用某个工具」通常是两个不同的答案，而模型那个问题更容易得到肯定。如果你想用的模型能通过某个你拿得到 key 的 provider 触达，dsh 就是那条路。

账号也是同理：每个工具各自登录、各自记账。Fleet 不自带模型账号，也没有托管订阅——所以你透过 Fleet 能触达的，恰好就是你本来就能触达的。

现在不在列上的

常被问到的那些——Cursor、opencode、ChatGPT 网页端、Kimi Code 等等——目前不在 Fleet 驱动的这三个里。这是在说 Fleet 的接入面，不是在评判它们；其中几个是很好的工具，只是围绕着与上面「CLI + 本地会话文件」不同的形态搭起来的。

如果你的活就长在其中某一个里，今天诚实的回答是：Fleet 起不了它。Fleet 仍然能替你做的是——如果你用的 provider 带着那家厂的模型，就通过 dsh 里的一把 provider key 去触达它们。模型能过来，工具过不来。

刻意混着用

因为计划、项目知识库与产出属于这件活本身而不属于某个 CLI，同一件活可以在这三个之间移动。一个工具拆方案、另一个实现步骤、第三个复审 diff——交接会带上计划、当前步骤，以及前一棒留下的笔记。

同时跑着好几个时，板上每张卡都标着它在哪个工具、哪个模型，所以混着跑的板仍然读得懂。哪一步交给哪个工具，是每件活各自的选择，不是你一次性定死的设置。

这一页就是为这些问题存在的

Fleet 能配 Cursor 用吗？+

目前不能。Fleet 驱动的是那种把会话留成本地文件、能被读取和恢复的命令行 agent；Cursor 是围绕它自己的编辑器与服务搭的，那属于另一种接入，而不是打开一个开关的事。

能配 ChatGPT 用吗？+

ChatGPT 应用本身不能。Codex 才是那个记在 ChatGPT 套餐上的命令行 agent，而它 Fleet 是驱动的——所以如果你手里是 ChatGPT 订阅，Codex 就是入口。

能用 DeepSeek、Qwen、Kimi 或者别家的模型吗？+

通常能，但是以「模型」而不是「工具」的身份：在 DeepSeek Harness 里配一把 provider key，Fleet 就按那家暴露的东西搭出选择器。某个具体模型在不在，取决于 provider，不取决于 Fleet。
