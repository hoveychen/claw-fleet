# rca 在应用里怎么用 — 现状盘点与设计方向

调研日期 2026-09-01。本文只记录**读代码读到的事实**和基于事实的设计选项，不含实现。
对应计划 `rca-ux-design`（explore，交付物是拆出来的 exec 子计划）。

---

## 一、rca 是什么（一句话）

agent（claude / codex）**仍在本机跑**，rca 把 workspace 路径下的文件读写和子进程
路由到远端执行器。所以 transcript、凭证、决策卡、用量统计全部留在本地原生工作——
这跟 RemoteBackend（整套搬远端）是**相反**的拓扑。

## 三、粗糙在哪（每条都有代码依据）

### A. 入口和心智模型对不上

用户心里想的是「我要在那台机器上干活」，应用要求他做的是「去设置页注册一个绝对路径」。
新建会话时那台机器不存在，只有一个路径字符串存在。

而且注册的第一个必填项就是最难填的：**两台机器完全一致的绝对路径**。用户得先自己
知道远端 repo 在哪、还得自己保证本机能创建同名路径（macOS 建不了 `/home/*`）。
这个硬约束只在一行灰色说明里带过，填错要等到点了安装才报错。

### B. 两个不同的「远端」在 UI 里同名

- **RemoteBackend**：整套 Fleet 搬到远端，本地只是壳。
- **rca 远端 workspace**：agent 在本地，只有文件 I/O 去远端。

界面上都叫「远端」。更麻烦的是数据模型已经缠在一起了：rca 安装向导的 ssh 目标选择器
直接复用 `list_saved_connections` 返回的 `RemoteConnection`——那是 RemoteBackend 的
连接记录。同一个下拉里同时混着 `~/.ssh/config` 别名和 backend 连接。

### C. 一个概念摆了两套并列入口，且共享输入框

「经 SSH 自动安装(推荐)」和「或手动注册(配对码)」两个表单上下并排。没有任何东西
告诉用户配对码那条是历史遗留路径（libp2p + 常驻 serve + 会变的码）。

更糟的是这两个表单**共用 `rwPath` 和 `rwLabel` 两个 state**
（`SettingsPanel.tsx` 里两处 JSX 绑同一对变量）：在自动安装表单里填了路径，
往下滚，手动表单里已经替你填好了；反之亦然。这不是设计，是复制粘贴的残留。

### D. 表单是一排裸 input，不是向导

一个 flex row 里横着塞：ssh 目标 select、`user@host` input、路径 input、
标签 input、安装按钮。没有分步、没有字段级说明、没有校验反馈——只有整体
`disabled`。进度是一列 `✓ / ▸` 的等宽文本行，装完不消失、不收起。

### E. 装完之后，应用里再也看不见 rca

`SessionCard` / `SessionList` / `SessionTabs` 里**零远端标识**（grep 无任何引用）。
会话一旦跑起来，从任何界面都看不出它的文件 I/O 正在另一台机器上发生。
唯一的标识只活在新建会话那个下拉的 sub 行里，选完就消失。

### F. 失败态是原始错误串

`wrap_launch` 的错误原样冒到 spawn 失败里：`rca binary not found`、
`workspace rcaPath points to X, which does not exist`。这些是给开发者读的。

会话跑起来之后 ssh 隧道断了会怎样——**这条我原先写错了，2026-09-02 实测更正**，
见第七节。

### G. 没有连通性自检

注册之后没有「测试连接」。一条条目是死是活，只有开会话才知道。
这次调研里那条 POC 遗留条目（指向早已不存在的 libp2p peer）就是我手工探针才
发现是死的——应用本身没有任何办法告诉你。

## 四、三个设计方向

### 方向 1 — 只打磨现状（最小改动）

保留「设置页注册路径」这个结构，把粗糙的地方逐个修：向导分步、拆开共享 state、
加测试连接按钮、会话卡片加远端标识、错误串翻译成人话。

- 好：范围可控，不动数据模型，每一条都能独立验收。
- 差：A 那条（心智模型对不上）修不掉——用户还是得先去设置页。

### 方向 2 — 入口前移到新建会话

设置页只留「远端主机」的管理（装 rca、健康检查）。新建会话时，workspace 选择器里
多一个「远端主机」维度：选主机 → **浏览它的目录树**（远端 browse）→ 选中即注册，
路径两边一致由应用保证而不是用户手填。

- 好：直接解决 A，用户再也不用手打绝对路径。
- 差：要新增远端目录浏览能力（ssh 侧列目录），且同路径约束在本机不可创建时
  （`/home/*` on macOS）还是得有个说法。

### 方向 3 — 远端主机做成一等公民

在方向 2 之上，把「远端主机」提到侧边栏/顶层：一台主机下挂它的若干 workspace、
显示在线状态、rca 版本、最近会话。rca 从「一个设置项」变成「一个你在里面干活的地方」。

- 好：概念最清晰，也顺手把 B（两个「远端」同名）掰开。
- 差：范围最大，且需要先想清楚它和 RemoteBackend 在导航上怎么共存。

## 五、还需要老板拍板的前置问题

1. **配对码那条路要不要留？** 留着就得一直解释两条路的区别；砍掉则 UI 少一半，
   但已注册的 pairing 条目要有迁移说法。（现在注册表里已经没有 pairing 条目了。）
2. **门控什么时候解？** 设计做完随之解除，还是等真机全链 e2e 跑通再解。
3. **RemoteBackend 和 rca 在导航上是并列还是分层？** 这决定方向 3 可不可行。

## 六、方向 2 的需求清单（老板 2026-09-01 选定方向 2）

> 每条标注来源。**「我加的」一律不写进实现计划，除非老板单独点头**——

### 6.1 老板明说的

| # | 需求 | 出处 |
|---|---|---|
| R1 | 设置页只留「远端主机」的管理（装 rca、健康检查），不再是注册路径的地方 | 方向 2 定义 |
| R2 | 新建会话时选主机 → 浏览它的目录树 → 选中即注册 | 方向 2 定义 |
| R3 | 路径两边一致由应用保证，不再由用户手打 | 方向 2 定义 |

### 6.2 由 R1–R3 直接推导的必要项

| # | 需求 | 为什么是必要项 |
|---|---|---|
| R4 | 远端目录浏览能力：给定 ssh 目标，列出某目录下的子目录 | R2 的「浏览目录树」没有它就不存在 |

### 6.4 方向 2 触发的新取舍 —— 老板 2026-09-01 已拍板

- **D1 · 砍掉配对码模式。** 「选主机 → 浏览目录树」要求有一个可 ssh 的目标；
  配对码只有一个 `rca1.…` 字符串，没有 ssh 目标，**无法列目录**。注册表里现在
  一条 pairing 条目都没有（今天刚清掉那条死的），迁移成本实际为零。
  **范围限 UI**：core 侧 `Transport::Pairing` 先留着不拆，免得同一轮里既改交互
  又动传输层。
- **D2 · 主机列表合一。** 一台 SSH 主机就是一条记录，上面挂两个能力：
  「当 Fleet 后端」(RemoteBackend) 和「当 rca 执行器」。这同时解掉 B 条
  （两个「远端」同名）。

### 6.5 老板点头带上的额外项

X1（会话界面远端标识）、X2（ssh 断线提示/重连）、X3（错误串人话）、
X4（条目「测试连接」）**四项全要**。X5（拆共享 state）是重做注册入口的副产品，
不单列。

## 七、ssh 断线时到底发生什么（2026-09-02 实测，两次复现）

本节更正第三节 F 里那句「ssh 断了 = 会话直接死」。**不是。真实情况更糟。**

### 实验

本机 rca v0.2.0，`--via` 指向一个可被 kill 的 ssh 包装脚本，远端 own-api-ko。
agent 每秒读一次只存在于远端的 `marker.txt`，跑到一半 `pkill` 掉那条 ssh。

### 观察到的（原始日志）

```
15:07:58 rca serve [fs] PREAD handle=2 off=0 len=6 -> 6
tick 1 ok
00:08:00 rca remote recv failed: stream reset: connection closed: EOF
tick 2 FAILED: FileNotFoundError: No such file or directory: '/private/tmp/ssh-kill-demo/marker.txt'
```

三件事，都与原先的假设不同：

1. **agent 进程没有死。** 它继续跑，只是从下一次系统调用起，看到的是本机那个
   **空的镜像目录**。
2. **agent 收到的不是传输错误，是 `FileNotFoundError`。** 从它的视角，这与
   「仓库被人删空了」完全无法区分。一个 agent 在这个状态下完全可能得出
   「代码没了」的结论，然后开始从头写。
3. **rca 自己是知道的。** 它在 stderr 上打了
   `rca remote recv failed: stream reset: connection closed: EOF`。信号是现成的，
   只是没有人把它接到界面上。

### 这对设计意味着什么

原先设想的「断线提示 + 可选重连」低估了严重性。真正的要求排序是：

- **P0 · 止损。** 一旦检测到断开，必须让 agent **停下**，而不是继续对着空目录
  工作。看到空仓库的 agent 会做出破坏性的错误决定。
- **P1 · 告知。** 会话上明确标出「远端连接断开」，并说清它停在哪一步。
- **P2 · 恢复。** serve 是 per-run 无状态的，重连不等于恢复现场——这是需要
  老板拍板的取舍（自动重跑 ssh 继续 / 只给一个「重开会话」按钮）。

信号来源已确定：rca 的 stderr。Fleet 本来就在收每个会话的 stderr
（`session_launch` 的 `stderr_log`），所以接这条线不需要改 rca。
