## 为什么是这一页

首页现在只用 title/description 覆盖了「Claude Code GUI / 桌面客户端」这类词。真正搜这些词的人带着一个具体问题来——「我已经在用 Claude Code 了，为什么还需要一个界面？」——而首页是讲定位的，不是回答这个问题的。一个专门回答它的页面能吃到长尾，也能把首页的定位说清楚而不必挤进首屏。

## 章节

每节都对应 `product-positioning.md` 里那张痛点表的一行，正文只写产品**已经有**的机制。

1. **H2：当你同时开着三个 agent**
   说：照看它们变成了工作本身。Fleet 的回应是按项目组织任务、统一发起、会话内继续/排队补充、决策聚合。配一张现有的会话板截图。
   **出处：**〔明说〕痛点表第 1 行，含对外话术「工作交给 AI，关键处你来接手」。

2. **H2：它问你能不能继续的时候**
   说：决策卡把方案、图片、HTML、关联文档和选项/表单放在同一张卡上，答案回到对应任务。
   **出处：**〔明说〕痛点表第 2 行，含「先看清方案，再给下一步」。

3. **H2：一件事做完了，东西在哪**
   说：产出库（预览/收藏/备注/导出）与知识库（版本/引用/导出）。
   **出处：**〔明说〕痛点表第 4 行。边界照抄：**不声称自动收一切**。

4. **H2：换个 agent 接着做**
   说：交接带上计划与当前步骤、前任留下的笔记；换工具也能接。三个工具各自的账号与配额不变。
   **出处：**〔明说〕痛点表第 5 行 + 首页 harness 段已有的口径。

5. **H2：这不能替你做什么**（诚实段）
   说：模型订阅与 API 用量仍在各家账单上；跑任务的机器要在线；语音是转写不是通话；Fleet 不自带模型账号，也没有托管云工作区订阅。
   **出处：**〔明说〕定位文档的「边界」与首页 FAQ 已有的口径。**这一节是我坚持要有的**〔我加的：把它单独成节而不是散在各处〕——搜「gui」进来的人第一个疑问就是「是不是又要另外付费」。

6. **H2：装完之后的三步**
   说：连接工具 → 交代第一件事 → 手机配对。直接复用首页 `getting-started` 的三步文案，不新写。
   **出处：**〔推导〕。

## 技术侧（不需要你决定，我会做掉）

## 明确不做的事

- **不做与其他产品的对比表。** 定位文档写了「差异化指值得强调的产品组合与体验，不等于宣称其他产品没有」——对比页最容易变成后者。
- **不写用户证言、评分、装机量。** 没有真实数据，编了就是给结构化数据埋雷。
- **不承诺零配置或下载即用。** 定位文档明确禁了这一条。
