# Fleet 的消费者定位与官网主线

**Boss 已选择 A「个人 AI 工作台」作为首页主线。** 手机接手为重点场景，自动化与长任务为深入功能。

这份提炼建立在 [当前产品调研](current-product-research.md) 上。产品机制有源码和当前 UI 证据；用户痛点与人群优先级是基于机制推导的定位假设，尚未做访谈、转化实验或完整竞品对比。差异化指“值得强调的产品组合与体验”，不等于宣称其他产品没有。

## 推荐定位

**个人 AI 工作台：交代任务，随时接手，带走成果。**

Fleet 把几件原本分散的事连到一起：选择 AI 和工作项目、推进与补充任务、看着材料做决定、收好文档与文件、从手机继续参与。消费者首先看到的是“我怎么把一件事做完”，之后再了解用了什么模型、怎么接续会话、哪里能看费用。

建议首要人群：已经开始用 AI 做项目、处理代码或资料，手上经常同时推进多件事的个人与小团队。不要在没有托管开户与免配置体验证据时，把它承诺成任何零基础用户下载即用的云端服务；但也不应把首页局限在看终端日志的工程师工具。

## 五个最值得讲的痛点

| 用户的真实处境（待访谈验证） | Fleet 已有的具体回应 | 对外如何说 | 应展示的当前产品证据 |
| --- | --- | --- | --- |
| “我同时开了几个 AI，越来越像在照看它们，而不是做自己的事。” | 项目下组织任务、统一发起入口、会话内继续/排队补充、决策聚合 | **工作交给 AI，关键处你来接手。** | 当前「工作→任务」侧栏 + 对话 + 待处理决定，不能只放满屏状态卡 |
| “它问我能不能继续，我还得翻上下文、找方案，才敢回答。” | 决策卡能带图片、HTML、关联文档、选项和表单，答案返回对应任务 | **先看清方案，再给下一步。** | 同一张真实决策卡：材料预览与回答动作并排；比一个假 Allow 按钮更有说服力 |
| “有个想法或需要答一句话，却得回电脑前处理。” | 手机新任务/语音转写/项目与设备选择，跨设备聚合任务和决定 | **想到了就交代，需要时随身接手。** | 当前手机新会话列表、输入区、待决定的任务；说明执行主机需在线 |
| “聊了很多，最后的文档、表格、方案又散在记录里。” | 独立产出库：预览、收藏、备注、导出；知识库：版本、引用、导出 | **成果能带走，经验能接着用。** | 同一任务对应的交付物 + 导出，再展示知识引用；必须是真实入库，不声称自动收一切 |
| “工作还没做完，聊天满了、CI没结束、重复任务又忘了。” | 长任务交接、计划树、事件等待、定时/循环与条件探测 | **把下一步安排好，不必一直盯着。** | 一个确实执行成功的接续或定时案例；别用无限运行的宣传口号 |

优先级建议：先讲前四项形成完整工作体验；第五项作为让复杂工作持续推进的深入功能。费用、审计、来源安装仍在功能页/FAQ 中清楚说明，不需要挤满首屏。

## 三个候选主张，如何选择

### A. 个人 AI 工作台（推荐）

**中文标题候选：交代任务，随时接手，带走成果。**
**英文标题候选：Give it the work. Make the calls. Take the results.**

说明文案候选：把 Claude Code、Codex 和 dsh 带进同一个工作台。按项目推进任务，看着方案做决定，把产出收好。在电脑上展开工作，也能从手机接手。

- 主角：人的工作与成果。
- 第一幅画面：当前任务工作区，打开一项有真实交付物的任务；材料/决定/结果能够连续演示。
- 优势：覆盖当前产品完整面貌，消费者容易理解；以后新增模型或平台也不必重写品牌定位。
- 代价：必须准备一条完整、有结果的案例；仅堆功能图标撑不起这个主张。
- 边界：“Take the results”描述查看/导出已产生的成果，不承诺模型必然正确或任何任务都能完成。

### B. 随身 AI 工作台

**中文标题候选：想到了，就让 AI 开始做。**
**英文标题候选：An idea can start anywhere. So can the work.**

说明文案候选：用手机交代任务，选择项目和执行设备。进度、决定和交付物，随时回来接着看。

- 主角：离开电脑的人、随手发起和接手。
- 第一幅画面：当前手机新会话与语音输入，随后接到桌面任务，再回到手机确认结果。
- 优势：一眼解释使用场景，移动体验成为记忆点。
- 代价：压低了桌面工作区、知识库与复杂任务管理的比重；容易被误解为手机本地 AI 或已有托管云服务。
- 边界：语音是转文字，运行主机要在线。没有真实公开手机安装地址前，以手机网页连接为主要入口。

### C. 长任务与自动化工作台

**中文标题候选：把下一步，也交代给 AI。**
**英文标题候选：Keep the next step in motion.**

说明文案候选：把任务写进计划，等条件准备好再继续，给重复工作排好日程。会话可以换，工作的脉络留下来。

- 主角：复杂任务、接续与定时工作。
- 第一幅画面：真实三步计划 + 一次接力 + 最终交付物；第二幅才是日程。
- 优势：容易把机制讲深，适合重度 AI/工程用户。
- 代价：比 A/B 更需要解释；“计划/接力”不一定是普通访客的第一需求。也最容易误写成永不停止或无限上下文。
- 边界：默认条件、最长执行周期、来源支持与失败恢复必须如实；不能宣传三种助手完全平价。

建议 **A 做首页，B 做主要场景，C 做深入功能**。这不是三套互相竞争的功能，而是选择哪件事先让消费者记住。

## 不建议继续使用的首页表达

- “AI 编程 agent 监控面板 / Mission control”：只覆盖一部分当前体验，而且让产物、纯聊天、任务和手机输入变成配角。
- “拥有无限 AI 员工 / 自动运行永不停止”：实现与使用前提不支持。
- “比 ChatGPT/Codex 更强 / 独有某能力”：本轮没有充分竞品与实际效果比较证据。它们首先还是用户可能接入的工具，不宜靠笼统贬低建立定位。
- “一个 App 搞定一切 / 任意文件自动归档”：既模糊，也超出真实能力。
- “免费 AI / 下载即有所有模型”：Fleet 免费开源，不等于模型订阅或 API 免费。

## 新官网的建议叙事顺序（定位确认后再实现）

1. **一句消费者主张 + 当前工作区。** 说明它是做工作的地方，主 CTA 下载，次 CTA 看完整工作过程。
2. **一个可验证的工作故事。** 例如资料/代码/表格任务的发起、补充、带材料决策、交付。具体案例要真实执行并取得最终产物后才写结果，不拿 fixture 数据冒充成功案例。
3. **离开电脑也能接手。** 使用当前手机新任务、设备/项目选择、语音输入、决策和产出页面。
4. **成果与下次工作的连接。** 产出预览/导出，wiki 版本与引用；证明“留存”不是口号。
5. **复杂工作的支持。** 长任务、条件触发、日程、多来源，清楚说明前提。
6. **下载与上手。** 当前真实平台与版本，GitHub + 已启用的国内线路；两语独立地址、国内不依赖外部字体/图片。

视觉以用户指定的 ChatGPT/Codex 网站的清晰度、留白和产品表达为质量基准；主角仍是 Fleet 自己当前的 UI 与工作过程，不能继续复用旧展示素材。

## 下一轮素材准入标准

- 从当前发布目标 commit 构建，而不是沿用 `docs/screenshots` 或旧 promo；若功能只在 main，明确先发布产品版本还是按稳定版介绍。
- 每幅截图注明来源版本、真实数据/演示数据；示例统计、占位日期不直接进官网。
- 每个“能做”的句子有当前 UI→服务调用证据。涉及可靠性、跨设备、语音或模型结果的承诺还需要对应端到端验证。
- 对话案例中的最后交付物必须实际存在、能打开并核对；没有做过就写“示例任务”，不写成“已生成”。
- 先确认上述 A/B/C 的主次，再重建中英文页面；当前旧版保持未合并，国内分发准备工作可以保留。
